# Nyx

**把读进去的英语，变成写得出来的英语。**

Nyx 接收一段英文 —— 一篇文章、一个段落、一句你自己存下来的话 —— 从里面挑出值得学的表达，
**每一条都带着它原本所在的那句话**。然后反复练，直到你能把它写出来，而不只是看懂。
桌面端负责阅读和重活，手机端跟着你进入手机上的每一个其他 App。

## 它想解决什么

大多数背单词工具都建在「认出来」上面：给你一个词和四个选项，你选一个，工具记下你「会了」。
但在选项里认出一个词，和在自己的句子中途把它调出来，是两种不同的能力。
很多人用这种方式「学」过几千个词，写出来的英文仍然平、仍然保守 —— 因为一路上没有任何一步
要求他产出过什么。

Nyx 从相反的假设出发：**一个表达是不是你的，唯一的证据是你把它产出过。**
下面所有的设计，都是从这一条推出来的。

## 它是怎么运转的

```
   贴进一段英文
        |
        v
   AI 分析  ────────>  知识点，每条都带着它的原文出处，
        |              并分成两层：
        |                理解层  —— 看懂就行
        |                写作层  —— 应该能写出来
        v
   练习 ──────┬──────>  认读练习   （认得出来吗）
              └──────>  产出练习   （说得出来吗）
                             |
                             v
                     四档判分 + 诊断
                             |
                             v
                   下一步练什么、什么时候练
```

## 它能做什么

### 阅读与析出

- 贴一篇文章，拿回一批知识点 —— 表达、句式、搭配 —— **每一条都带着它被取出来的那句原文**。
  没有出处的东西不进库。
- 存下你自己收集的句子，让它把成分拆开。
- 让 AI 导师陪你读一篇文章。
- 对任意一条知识点要一份完整解析：它怎么用、什么时候用、它不是什么。

### 练习

- **认读练习**和**产出练习**，刻意分开。
- 产出题型只有五种，**里面没有选择题** —— 也没有连线题，没有给选项的完形填空。
  答案只要出现在屏幕上，这道题量的就不是它该量的东西。
- 作答按**四档语用刻度**判分，并且判分必须可复现：
  同一份作答今天判 3 档、明天判 2 档，进度就成了随机数。
- 诊断分两个方向：纵向看一条知识点的变化，横向看一轮练习的全貌。

### 你的词库

- 知识点按 Lecture 和单元组织。没有东西会被悄悄扔掉。
- 练完不想再见的条目转为**静默**，不是删除 —— 它不再出现，但它没有消失。
- 删掉的条目在回收站里待十天，然后才是真的没了。
- 本地词典支持两种格式：**MDict**（`.mdx`，配 `.mdd` 资源包）和 **StarDict**（`.ifo`）。
  没有词典也照常用 —— 例句改由 AI 生成，并且会标明是 AI 生成的。
- 朗读：可以用词典自带的发音，也可以用系统或云端语音。

### 你的数据

- 全部在一个 SQLite 数据库里，就在可执行文件旁边的 `data/`。
  复制这一个文件夹，就等于把整套装置搬到了另一台机器。
- 数据库**只增不删**：编号迁移、每次启动自动备份、升级结构之前再备份一次、
  保留最近十份、升级失败自动回滚。
- 两端之间可选同步，走 **WebDAV** 或 **Supabase Storage**。
  同步凭据留在本机，API key 也一样 —— 两者都不会上传。

## Windows 和 Android 不是同一个 App

两端共用一份 core —— 同一套析出判据、同一套判分、同一份库结构 —— 但它们是**刻意不对称**的。

| | Windows | Android |
|---|---|---|
| 读长材料、做分析 | 主要在这里做 | 不做，这是设计 |
| 收集一句你喜欢的话 | 可以 | 可以 |
| 在**别的 App 里**查词 | — | 可以，这正是它存在的理由 |
| 练习（认读 + 产出） | 可以 | 可以 |
| 单条解析 | 可以 | 可以 |
| 改一条的词与释义 | 可以 | 可以 |
| 报告、统计、排期 | 可以 | 不做，这是设计 |
| 改归类、改归属 | 可以 | 不做，这是设计 |

手机端是给排队时那几分钟用的，不是第二台桌面。它最不一样的地方是 **Assist**：
一个无障碍服务，让你在任何别的应用里 —— 浏览器、聊天、PDF 阅读器 —— 选中一段文字就能查词、
或者存进词库，全程不用离开那个应用。

## 你会注意到的几条设计取舍

- **每一条知识点都带原文出处。** 脱离了出现语境的表达是一张卡片，不是一段语言。
- **AI 不做整句翻译。** 释义尽量用英文，只有语法说明用中文。
- **提示词是文件，不是代码。** AI 做的每件事都写在 `prompts/*.md` 里。
  用记事本打开、改完存盘，下次分析就用你改的那份；删掉它，内置的那份接管。
- **静默不是删除，删除也不是立刻。**
- **界面不持有数据副本。** SQLite 是唯一真相，界面从不直接碰数据库和 AI。

## 上手

### Windows

1. 解压到 `C:\Program Files` 以外的任何地方 —— `D:\Nyx` 这类位置就行。双击 `Nyx.exe`。
2. 设置 → AI：把 OpenAI 兼容的 API key 贴进去，保存，再点**测试连接**。
   key 加密保存，只存在这台机器上，不上传、不参与同步。
3. 首页 → 开始：贴一段英文，跑分析。
4. 看一遍析出的东西，然后开始学。
5. 可选 —— 词典：每本词典连整个文件夹放进 `data/dicts/`，然后设置 → 词典 → 重新扫描。

包里随带《使用说明.md》。

### Android

1. 侧载安装 APK，系统会让你允许「来自未知来源」。
2. 设置 → AI：填 API key。规则一样 —— 只存本地，不上传。
3. 要用 **Assist**，需要你自己去 Android 系统设置里**手动授予无障碍权限**，
   App 里不会有任何地方主动提示你。
4. 可选 —— 配好同步，让手机和电脑共用一个词库。

需要 Android 6.0 以上。

## 项目状态

**v0.1.0。** 上面描述的那条闭环在两端都能完整跑通。
碰你数据的那几块 —— 迁移、备份、同步、删除 —— 是被测得最狠的，因为它们是会弄丢东西的那几块。
这不是一个产品：没有支持渠道，没有路线图承诺，界面只有中文。

本仓库是**当前代码的快照，只有一个提交**，公开出来供阅读。
开发历史、设计文档和问题清单不在里面。

## 自己构建

```
npm install
npm run dev
```

`windows/` 和 `android/` 是两个独立工程，各自在自己目录里构建。

在私有开发仓里，`android/nyx-core/` 是一个 git submodule，指向桌面端仓库并锁定 commit SHA ——
共用的代码**只存在一份**。这里把它实体化成了普通目录，好让这份快照能独立 clone 下来构建，
所以 `windows/src/core/` 和 `android/nyx-core/src/core/` 在本仓库里看起来是重复的。

图标和启动图的成品都在，两端构建不缺东西；但生成它们用的原图没有公开，
所以 `scripts/gen-brand-icons.mjs` 和 `scripts/gen-splash-art.mjs` 在这里跑不起来。
这是有意的，不是缺文件。
