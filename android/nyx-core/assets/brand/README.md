## 二、三个不是随手定的做法

★★ **2026-09-14 换成兔子之后，这三条变成了「看原图走哪一条」** ——
生成链自己量一下原图有没有**大片透明**（实测兔子 64.1% 的像素 alpha=0，水獭那张是 0）：
有 → 透明底那一条；没有 → 白瓷砖那一条。**两张原图都还能重跑**。

1. **Android 前景不带底。** 自适应图标由系统再套一层遮罩，底色得交给 background 层。
   · **白瓷砖那一条**（水獭）：两段洪水填充把主体从瓷砖里抠出来 —— 不能按亮度阈值抠，
     那只水獭的脸和胸口本来就跟瓷砖底一个亮度。
   · **透明底那一条**（兔子）：底本来就是透的，**只跑第一段**。
     ★ 第二段千万不能跑：它会从**主体自己的包围盒内侧**灌白，而这只兔子
     63.2% 的不透明像素亮度 > 0.86（它整只就是白的）—— 灌下去耳朵内侧、脸、
     眨眼那一侧的白会被连成一片吃掉，只剩一圈深蓝描边。
   · **不能只留最大连通块**（旧版就是这么写的）：兔子左边那**两颗星光**是独立块
     （实测 4590 px 与 1234 px，本体 559183 px），只留最大块会把它们整个删掉。
     现在按大小筛：≥ 32 px 的都留（噪点实测只有 1 px 与 2 px 各一处）。
2. **有平底的贴地，没平底的居中。** Android 只保证中间 72dp 可见。
   水獭的身子顶着瓷砖下沿、抠出来底是平的，摆到正中会像悬空一块，所以贴地；
   兔子是**一颗浮着的头**，没有地面。照旧贴地的实测后果是：可见区里上边留 17 px、
   下边只剩 **1 px**（xxxhdpi，可见区 288 px）—— 三种标准遮罩还没切到下巴，
   但再狠一点的厂商遮罩就会切。改成居中之后上下各 9 px。
3. **有富余留白才收紧构图。** 16px 一共只有 256 个像素。
   水獭那张的 Master 里主体外面除了 4% 补边还有瓷砖内部的空白，所以
   16 / 24 / 32 / 48 分别多裁 10% / 9% / 7% / 4%，**裁的是留白不是图**。
   兔子那张没有那圈空白 —— 照搬的实测后果是 16/24/32/48 四档**四条边全部贴边**
   （16 档上 8 下 11 左 4 右 7 个像素顶在边上），也就是**耳尖和下巴被切掉**。
   所以透明底那一条四档全是 0：**只缩放，不裁**。

## 三、两条要知道的限制

- **16px 上它只是一团浅蓝。** 这是低多边形胸像 + 16 像素的物理极限，不是没调好；收紧构图已经把能捞的捞回来了。
  真要在 16px 上认得出，得为小尺寸单画一版极简形 —— 那属于「重新设计」，使用者明令不做。
- **这套图标与 UI 里暂定的标志 M3（夜之眼）是两张不同的脸。** App 图标是这个软件最显眼的品牌形象；
  两个形象并存会互相削弱。**建议由使用者裁一句**：以水獭为准（M3 撤下），还是水獭只做 App 图标、M3 继续做界面里的标记。
